# 这轮实验说明了什么

本轮在用户分支完成四组、每组 200 条固定 Dev 的真实调用。所有组采用相同四条有效 Train 示例、类别定义、解析器与两级主评估器。
它检验的是字符索引展示与终点解释，不重复 main 的示例数量实验，也没有复制或合并 main 的 Test 结果。

## 有证据支持的观察

- 普通索引+简短说明（A）有 6/200 句话出现坐标错误；三列边界索引+简短说明（B）为 1/200。
- A→B 的实体 F1 为 73.66%→74.23%，差值 +0.57 个百分点，配对 bootstrap 95% 描述区间 [-1.50,+2.70]。
- 对应坐标错误率差为 -2.50 个百分点，区间 [-5.50,0.00]。观察到减少，但样本量和区间不足以宣称稳定的普遍提升。
- 只加终点解释的 C，实体 F1 为 73.59%；组合 D 为 73.52%。没有观察到详细解释带来额外实体 F1 提升。
- D 的 Token F1 最高（79.00%），B 的实体 F1 最高（74.23%），再次表明指标的判断粒度不同；这不是更换选参标准的理由。
- B 比 A 的输入 token 总量高约 27%，网络中位数均约 0.91 秒。表示改进有输入长度成本，不能只展示受益数字。

这些区间未做多重比较校正；单次生成、Dev 探索与此前查看 main 的背景均限制结论。不要写“证明三列索引必然提高 NER 准确率”。

## 两个真实案例把问题分开

### 坐标一致性问题：dev:1189

原文：今天看完这个项目以后，可能在座的各位，尤其建筑设计师们都是一些大家，都是行家里手，

原标注：`建筑设计师`，position，`[21,26)`。

A 输出 text=`建筑设计师`、start=21、end=25。实体文字对，但切片 `原文[21:25]` 少了“师”，属于输出内部不一致。
B、C、D 都输出同样文字和类别，坐标 `[21,26)`，与原标注匹配。
这支持“至少有部分失败发生在坐标表达，而非实体文字没有被发现”；仅凭一个案例不能解释整个模型差距。

### 坐标正确仍未完成实体抽取：dev:689

原文：地址：北京市朝阳区朝外大街吉祥里208号民建中央239室

原标注把 `[3,28)` 整段标为一个地址。
A 对 `北京市朝阳区朝外大街吉祥里208号` 给出 `[3,19)`，文字与坐标不一致。
B 对同样短地址给出正确自洽的 `[3,20)`，但它仍不是标准答案要求的完整 `[3,28)`，并把后面的机构拆出来。
因此，消除坐标问题不等于解决了标注范围和语义边界问题。

两个案例原始预测都在本地四组 predictions.jsonl；自动诊断尚未替代两人的独立人工核验。

## 为什么文字+类别 bag F1 不能当作上界

A 的 bag F1 为 73.53%，略低于规范化实体 F1 的 73.66%。原因是两套诊断采用的预测条目范围不同：主评估排除无效实体，bag 保留有文字和类别的输出并忽略坐标。
所以不能把二者差值直接当作“由定位造成的损失”，也不能说“只修好坐标就能达到 bag 分数”。应结合坐标错误条目、原始跨度分数和真实案例解释。
