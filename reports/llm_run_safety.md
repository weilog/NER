# LLM 运行保护与手动操作

本次仅修整工程保护，不更改 SYSTEM 提示、类别定义、模型参数、输出 schema、示例选择算法和评估口径。没有调用 API 或重新生成预测。

## 新实验如何启动

以下命令会产生真实 API 调用，请准备好后自行运行；这里没有执行这些命令。

```powershell
.\.venv\Scripts\python.exe scripts/run_llm.py --stage pilot --output-dir runs/llm_review
.\.venv\Scripts\python.exe scripts/run_llm.py --stage dev --output-dir runs/llm_review
```

先检查 20 条 pilot 的结果，再运行 Dev 阶段。默认调参比较 0、2、4、8 个示例。若在实验开始前决定减少调参调用，可在两条命令中均增加 `--tuning-shots 0 4`。这会保留同一 300 条调参样本和完整 Dev，只减少候选方案；将选择过程写成“在 4-shot 候选方案下完成验证”，不要声称从 2/4/8 中选出了最优。

## 运行前与缓存保护

- 在构造 Client 和发请求前，核对实际数据哈希、配置、完整示例内容、pilot/tuning ID、提示、价格配置、候选示例数及相关代码。
- 新目录保存自己的示例 ID，不改写原 `data/splits` 中的示例记录。
- 原来的 `runs/llm` 和旧缓存没有新增校验信息，受保护，不能自动续跑或自动迁移。旧预测仍可用于既有离线重评。
- 新缓存保存完整请求（不含认证头/密钥）、原始响应、解析结果和内容哈希。读取时校验请求、内容哈希，并重新解析原始响应比对状态和实体。
- 完整结果组验证四类结果文件哈希后直接复用。损坏、旧版本、部分写入结果的目录会停止，保留现场。
- 请求过程中中断、尚未写结果文件时，可重复相同命令，复用已成功落盘的请求缓存。若响应后、缓存落盘前崩溃，该请求可能重发；保留的预算预留防止把不确定费用当作零。
- 多个实验输出目录共享进程锁；意外崩溃可能留下锁，确认没有进程正在调用后再人工处理。

## 预算与统计

新输出目录必须位于项目 `runs/` 内。启动时累计其他目录 `ledger.json` 的已记账费用上界，并从 100 元总上限和 20 元调参累计上限中扣除；换目录不会重置已有费用。账本副本放在 runs 外，避免重复统计。预算估算基于当前本地价格配置，实际账单仍以服务商为准。

预算不足时停止并保留缓存，不自动充值、不改变 Test、不按中途分数删减候选或样本。减少候选必须在新实验开始前显式指定并记录，无法保证剩余预算一定足以完成全部阶段。

缓存中的延迟表示最初请求耗时（含该请求的重试等待），不是本地缓存读取速度；复用结果组时保留原始统计。记录中的 ledger_upper_cny 是该 Client 账本累计费用上界，不是单个结果组的独立花费。

## 与旧正式实验的关系

新目录的选参结果不会自动替换 `run_final.py` 仍引用的旧目录。源代码变化也会触发旧正式实验冻结校验；不要删掉冻结文件以强行重跑 Test。

尚未加入输出实体 text 的新提示版本，因此仍不能独立区分“实体识别错误”与“字符索引错误”。这属于后续实验协议变化，不在本次工程修整中隐式加入。
