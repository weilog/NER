## 预测接口与同源评分

一个字符指 Python Unicode 码点；所有方法直接使用原文，不 trim、不做 Unicode 标准化，也不按 UTF-16 或 UTF-8 长度编号。
一个成功样本示例：

```json
{"id":"train:100","status":"ok","entities":[{"start":0,"end":2,"type":"name","text":"张三"}]}
```

`entities` 中的 `text` 对通用评估器可选，LLM 提示协议要求提供。索引必须为整数（布尔值不算整数）。
传统方法可以同时保存 `raw_bio_tags`；如还提供 `entities`，它必须与 BIO 修复后派生的跨度一致，否则视为文件错误。
缺失、重复、多余的样本 ID、未知状态、成功样本缺少实体列表/BIO、BIO 长度或标签格式错误，停止整个文件评分。
显式失败状态为 `api_error`、`parse_error`、`budget_stopped`、`error`；均按空预测计分，独立报告失败率。

主结果仅采用统一规范化器产生的一个集合：

1. 原始 BIO 的孤立或类别变更 I 修复为对应 B，记录修复前非法转移数；每句首也算转移位置。
2. 校验跨度结构、范围、类别及可选实体文本；无效条目记录原因，从两套主指标共同排除，不搜索原文自动纠正位置。
3. 相同 `(start,end,type)` 去重；不同重复条目的文本分别校验，有效条目不因无效副本而丢失。
4. 有效跨度按起点升序、长度降序、类别名升序排序，贪心保留非重叠实体。
5. 该同一实体集合同时进入严格实体评分和 BIO 字符评分。

无效实体不再按旧协议混入主实体 FP。必须同时披露原始跨度诊断分数、无效输出率、重复数和重叠删除数，避免仅报告清洗后的结果。
原始跨度诊断按所有结构可解析的整数起止位置与字符串类别组成集合计分，越界和未知类别可形成 FP；结构不可解析条目仅进入无效统计。
该诊断只看原始坐标和类型，文本不一致单独报告，不等同于通过文本校验后的评分。

Token 主指标为 20 个非 O BIO 标签的 micro P/R/F1；真实与预测非 O 标签不同（含 B/I 混淆）同时计 FP、FN。
O→O 不贡献 TP；所有字符位置仍参与统计。严格实体匹配要求句子 ID、起点、终点、类别全部一致。
每类实体结果、固定十类宏 F1、含 O 字符准确率另外报告。零分母对应分数为零，并保存 TP/FP/FN。

敏感性结果：保存原始 BIO 的 Token 分数；严格 BIO 实体解析只允许 B 开始、同类 I 延伸，孤立 I 不产生实体。
上述 BIO 敏感性仅针对提供原始 BIO 的样本，明确披露覆盖样本数，不当成跨方法主排名。
非法转移率分母为提供原始 BIO 的字符总数；无效实体率分母为成功样本的实体条目总数（包括重复），分子为逐条校验失败的条目数。
失败率、无效样本率、重叠影响率分母均为评估文件全部样本数。

## 实验边界与待完成项

非大模型主结果为词典、BIO 约束 HMM、CPU CRF，以 Dev 实体 micro F1 选参。
HMM 普通 Viterbi 与约束 Viterbi 在相同参数下对照，两者都按统一规范化协议评分，并披露修复前非法转移率。
所有五组方法属于不同任务监督条件下的系统比较，不能推导一般架构优劣；Zero-shot 不保证预训练未接触公开数据。

LLM 固定 `deepseek-flash`、关闭 Thinking、`temperature=0`、JSON 对象输出；不保证完全确定，必须保存原始响应和完整请求缓存。
试跑后才能冻结输出上限、超时、并发与当日价格。总预算 100 元，包含重试；应预留完整 Dev 和正式 Test 的费用。
JSON 语法合法不代表实体 schema、类别或位置正确；空响应、截断和解析失败都应有明确状态。
本阶段没有调用 API，因此没有试跑、预算停止、恢复或 API 异常的实现验收结果。

后续还需完成模型实验、真实预测案例与错误一对一归因、人工复核，以及 2,000 次句子级配对 bootstrap。
Bootstrap 每次汇总句子 TP/FP/FN 后重算全局 micro F1，区间不包括重训练及 LLM 重复调用波动。
正式 Test 只在全部参与比较的配置冻结后运行。当前代码不启动任何 Test 模型实验。

## 本机复现

在项目根目录执行：

```powershell
.\.venv\Scripts\python.exe scripts\prepare_cluener.py
.\.venv\Scripts\python.exe scripts\prepare_split.py
.\.venv\Scripts\python.exe -m pytest tests -q
.\.venv\Scripts\python.exe scripts\evaluate.py --gold data\processed\experiment_v2\dev.jsonl --predictions runs\METHOD\dev_predictions.jsonl --output runs\METHOD\dev_metrics.json
```

最后一条需使用实际预测文件；当前传统模型的 Dev 预测保存在 `runs/traditional_dev/`，最终五组方法 Test 主表仍待后续阶段。
评分器输出原始计数、逐句计数、输入哈希及规范化诊断文件，支持保存预测后的离线重算。
